# 개발 표준 운영

## 적용 범위

2026-11-16에 개발 지침을 시범 도입했다. 제품 동작과 PWA 품질 검증 완료 상태는
이번 도입의 범위가 아니다. 제품 문서의 소유권과 검증 절차는 루트
[AGENTS.md](../AGENTS.md)에서 연결한다.

적용 원본과 파일 해시는 [.development-standard/standard-lock.json](../.development-standard/standard-lock.json)이
소유한다. 표준 사본은 오프라인에서도 읽을 수 있으며, 원격 기본 브랜치의 변경을 자동 반영하지 않는다.
프로젝트별 판단은 기존 문서에 기록하고, 고정한 표준 사본은 직접 수정하지 않는다.
잠금 파일은 출처 선언과 무결성 확인용이며 전자서명이나 품질 인증이 아니다.

## 무결성 확인

저장소 루트의 PowerShell에서 다음을 실행한다. Python이나 외부 패키지는 필요하지 않다.
정책·스키마·규칙 파일, 관리 구간, 줄바꿈 설정을 잠금 파일의 해시와 비교한다.

```powershell
$standardRoot = Join-Path (Get-Location) '.development-standard'
$standardLock = Get-Content -Raw -Encoding UTF8 (Join-Path $standardRoot 'standard-lock.json') | ConvertFrom-Json
foreach ($entry in $standardLock.files.psobject.Properties) {
    $actualHash = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $standardRoot $entry.Name)).Hash.ToLowerInvariant()
    if ($actualHash -ne $entry.Value) { throw "Standard drift: $($entry.Name)" }
}
$attributesHash = (Get-FileHash -Algorithm SHA256 -LiteralPath $standardLock.integration.attributesFile).Hash.ToLowerInvariant()
if ($attributesHash -ne $standardLock.integration.attributesDigest) { throw 'Attributes drift' }
$agentsText = [IO.File]::ReadAllText((Join-Path (Get-Location) $standardLock.integration.agentsFile)).Replace("`r`n", "`n")
$startMarker = '<!-- ai-development-standard:start -->'
$endMarker = '<!-- ai-development-standard:end -->'
if ([regex]::Matches($agentsText, [regex]::Escape($startMarker)).Count -ne 1 -or [regex]::Matches($agentsText, [regex]::Escape($endMarker)).Count -ne 1) { throw 'Invalid managed markers' }
$sectionMatch = [regex]::Match($agentsText, '(?s)<!-- ai-development-standard:start -->.*?<!-- ai-development-standard:end -->')
if (-not $sectionMatch.Success) { throw 'Invalid managed section' }
$hashAlgorithm = [Security.Cryptography.SHA256]::Create()
try {
    $sectionHash = ([BitConverter]::ToString($hashAlgorithm.ComputeHash([Text.Encoding]::UTF8.GetBytes($sectionMatch.Value)))).Replace('-', '').ToLowerInvariant()
} finally { $hashAlgorithm.Dispose() }
if ($sectionHash -ne $standardLock.integration.sectionDigest) { throw 'Agent guidance drift' }
'Standard integrity: passed'
```

이 검사는 잠금 파일과 현재 사본 사이의 변경을 탐지한다. 잠금 파일 자체의 변경은
Git diff로 검토하고 원본 커밋과 대조한다. 제품 기능이나 표준 준수 전체를 판정하지 않는다.

## 갱신과 충돌

1. 별도 브랜치에서 현재 무결성을 확인한다. 실패하면 덮어쓰지 않고 변경 원인을 검토한다.
2. 원본 저장소의 전체 커밋 SHA를 선택하고 해당 커밋의 정책 변경을 검토한다.
   새 정책이 프로젝트 경계나 승인 요건을 바꾸면 ARCH 기준에 따라 승인을 받는다.
3. 원본 커밋의 `standards/*.md`, `schemas/project.schema.json`,
   `schemas/roadmap.schema.json`, `schemas/task.schema.json`, `rules/catalog.json`만
   LF 바이트로 복사한다. 프로젝트 파일과 기존 제품 문서는 교체하지 않는다.
4. 파일별 SHA-256과, 경로순으로 정렬한 해시 맵을 공백 없이 JSON으로 직렬화한
   UTF-8 바이트의 SHA-256으로 `standardDigest`를 계산한다. 기존 표준 관리기의
   digest 알고리즘을 유지한다. 원본 커밋의 바이트와 복사본이 같은지 확인한다.
5. AGENTS 관리 구간은 시작 마커부터 끝 마커까지 포함하고 끝 마커 뒤 줄바꿈은
   제외하여 CRLF를 LF로 정규화한 후 SHA-256을 계산한다. 구간 밖 지침은 보존한다.
6. 원본 커밋·해시·잠금 파일·정책·지침의 diff를 함께 검토한 후 위 검사를 다시 실행한다.
   관리 파일이나 관리 구간이 편집되어 있으면 자동 교체하지 않는다.

`schemas/` 사본은 향후 필요한 구조화 문서를 검증하기 위한 참고 계약이며,
현재 제품 문서를 JSON으로 전환하라는 요구가 아니다. 중앙 관리 레지스트리의
도입 선언은 이 브랜치의 실제 적용 바이트 검증 후 별도로 동기화한다.

## 복구와 후속 검증

갱신을 복구할 때는 해당 도입·갱신 커밋이 변경한 파일만 이전 바이트로 복원하고
무결성을 다시 확인한다. 최초 도입을 취소할 때는 추가된 `.development-standard/`,
이 운영 문서와 README 링크를 제거하고 AGENTS의 관리 구간만 제거한다.
다른 지침이 추가된 AGENTS 파일은 유지한다. 프로젝트 전체를 reset하지 않는다.

도입 이후 실제 제품 개발 작업 한 건에서 정책 탐색, 영향 분류, 적용 가능한 문법 검사와
수동 검증을 수행한 근거를 남겨야 시범 도입의 효과를 평가할 수 있다.
이후의 제품 변경과 다른 저장소로의 확대는 각각의 작업 범위에서 진행한다.
