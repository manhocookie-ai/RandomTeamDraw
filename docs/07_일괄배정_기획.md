# 랜덤 조 편성 — 일괄 배정 기획

## 문제 정의

현재는 이름을 입력하는 즉시 조가 결정된다. 최소 인원 조 우선 규칙 때문에 입력 순서가 바뀌면
각 사람이 배정되는 조도 달라질 수 있고, 사용자는 먼저 입력된 사람이 특정 조를 선점한다고 느낄 수 있다.

입력과 배정을 분리해 참가자 명단을 먼저 완성한 뒤 한 번에 섞고 배정한다. 화면에는 계산된 결과를
무작위 순서로 하나씩 공개해 카드가 각 조로 연속해서 이동하는 경험을 제공한다.

## 핵심 흐름

```text
이름 입력
  → 배정 대기 명단에 누적
    → “명단 셔플”로 카드 순서 섞기(선택)
      → “N명 조 편성 시작”
        → 셔플하지 않았다면 자동 셔플
        → 전체 배정 결과 계산·저장
          → 카드가 무작위 순서로 각 조에 연속 이동
```

입력 순서는 보존할 필요가 없다. 실제 배정 순서와 공개 순서는 입력 순서에서 분리한다.

## 배정 알고리즘

1. 아직 배정되지 않은 참가자 ID 목록을 만든다.
2. 사용자가 셔플한 대기 순서가 있으면 그 순서를 사용한다.
3. 사용자가 셔플하지 않았다면 `조 편성 시작` 시 `crypto.getRandomValues()`를 사용하는
   Fisher–Yates 방식으로 목록을 자동으로 한 번 섞는다.
4. 섞인 순서대로 `현재 배정 인원 + 조별 가중치`가 가장 작은 조를 선택한다.
5. 최솟값이 같은 조가 여러 개면 암호학적 난수로 하나를 선택한다.
6. 모든 결과를 메모리에서 먼저 계산한다.
7. 참가자별 조, 최근 공개 참가자 ID, 대기 상태를 한 번에 저장한다.
8. 저장이 성공한 뒤 결과 공개 애니메이션을 시작한다.

따라서 사용자가 이름을 입력한 순서는 배정 순서로 사용되지 않는다. 동일한 명단으로 다시 추첨하면
난수 때문에 결과가 달라질 수 있으며, 이는 의도된 동작이다.

## 화면 상태

### 1. 명단 입력 중

- 왼쪽에는 참가자 이름과 `대기` 상태를 표시한다.
- 조 카드에는 아직 이름을 표시하지 않는다.
- 하단에 `명단 셔플`과 `N명 조 편성 시작` 버튼을 함께 표시한다.
- 대기 참가자가 없으면 시작 버튼을 비활성화한다.
- 대기 참가자가 두 명 미만이면 셔플 버튼을 비활성화한다.
- 이름 수정과 삭제는 자유롭게 허용한다.

### 명단 셔플 버튼

`명단 셔플`은 참가자를 조에 배정하지 않고 대기 카드의 순서만 무작위로 바꾼다. 사용자는
뒤섞이는 과정을 눈으로 확인한 뒤 `조 편성 시작`을 누른다.

#### 셔플 동작

1. 대기 참가자 ID를 암호학적 Fisher–Yates 방식으로 섞는다.
2. 셔플 애니메이션 중 입력, 수정, 삭제, 설정, 초기화와 중복 셔플을 잠근다.
3. 카드가 잠깐 중앙으로 모였다가 새 위치로 퍼지는 방식으로 순서를 바꾼다.
4. 애니메이션이 끝나면 새 대기 순서를 화면에 유지한다.
5. 사용자는 배정 전까지 셔플을 다시 실행할 수 있다.
6. 참가자를 추가·수정·삭제하면 현재 순서는 유지하되 `조 편성 시작`은 현재 대기 목록 전체를 사용한다.

#### 셔플 연출

- 카드가 80~120ms 간격으로 살짝 들리며 중앙 방향으로 겹친다.
- 짧은 흔들림 또는 좌우 교차 후 새 순서의 위치로 이동한다.
- 전체 셔플 시간은 인원수와 관계없이 약 0.8~1.5초 안에 끝낸다.
- 30명 이상이면 개별 카드 이동 대신 목록 전체가 섞이는 축약 연출을 사용한다.
- `prefers-reduced-motion`에서는 애니메이션 없이 순서만 즉시 바꾼다.

셔플 애니메이션은 난수 생성 결과를 보여주는 표현일 뿐이다. 애니메이션 프레임이나 카드 좌표를
난수 입력으로 사용하지 않는다.

### 2. 배정 연출 중

- 입력, 수정, 삭제, 설정, 초기화 버튼을 잠시 비활성화한다.
- 화면 중앙 또는 최근 배정 영역에 참가자 카드를 크게 표시한다.
- 카드가 대상 조 카드로 이동하며 축소된다.
- 다음 카드가 이어서 나타나 같은 동작을 반복한다.
- 전체 연출은 참가자 수가 많아도 지나치게 오래 걸리지 않게 조절한다.

권장 간격:

- 1~12명: 카드당 약 350ms
- 13~30명: 카드당 약 220ms
- 31명 이상: 카드당 약 100ms
- `prefers-reduced-motion`: 이동 없이 즉시 전체 결과 표시

연출은 이미 계산·저장된 결과를 보여주는 표현일 뿐이며 배정 결과를 바꾸지 않는다.

### 3. 배정 완료

- 네 조 카드에 전체 결과를 표시한다.
- 마지막으로 공개된 참가자를 결과 카드와 조 목록에서 강조한다.
- 시작 버튼은 대기 참가자가 생기기 전까지 숨기거나 비활성화한다.
- 완료 인원과 조별 인원수를 즉시 확인할 수 있다.

## 늦게 온 참가자

배정 완료 후에도 새 이름을 추가할 수 있다. 새 참가자는 기존 결과를 바꾸지 않고 `대기`로 표시한다.
버튼은 `대기 N명 추가 배정`으로 바뀐다.

추가 배정 시:

1. 기존 조 인원과 가중치를 기준으로 한다.
2. 대기 참가자끼리 먼저 섞는다.
3. 기존 참가자의 조는 절대 변경하지 않는다.
4. 새 참가자 카드만 연속 이동한다.

이 방식은 지각 참가자를 처리하면서 전체 재추첨을 피한다.

## 재추첨 정책

실수로 결과를 바꾸는 일을 막기 위해 별도 `전체 재추첨` 버튼은 기본 화면에 두지 않는다.
처음부터 다시 배정하려면 전체 초기화 후 명단을 다시 입력하는 현재 원칙을 유지한다.

향후 실제 수요가 확인되면 `조 배정만 초기화`를 별도 기획할 수 있지만 이번 범위에는 포함하지 않는다.

## 저장과 중단 복구

- 배정 결과는 애니메이션 전에 한 번에 저장한다.
- 애니메이션 도중 브라우저를 닫아도 재실행하면 최종 배정 결과를 표시한다.
- 공개 애니메이션의 중간 진행 위치는 저장하지 않는다.
- 배정 전 대기 카드의 표시 순서는 세션에 저장한다. 셔플 후 새로고침해도 같은 순서를 보여준다.
- 저장 실패 시 애니메이션을 시작하지 않고 기존 대기 상태를 유지한다.
- 전체 초기화는 참가자와 배정 결과를 지우되 조 이름과 가중치는 유지한다.

## 접근성

- 배정 시작 버튼에 현재 대기 인원수를 텍스트로 표시한다.
- 결과 공개 중에는 현재 참가자와 조 이름을 라이브 영역으로 안내한다.
- 동작 줄이기 설정에서는 카드 이동과 지연을 모두 생략한다.
- 색상뿐 아니라 이름과 조 이름을 항상 문자로 표시한다.
- 애니메이션 종료 후 포커스를 결과 요약 또는 이름 입력으로 이동한다.

## 완료 기준

- 입력 순서와 실제 배정 순서가 분리된다.
- 셔플 버튼을 누르면 대기 카드가 암호학적으로 섞이고 새 순서가 저장된다.
- 셔플을 누르지 않고 시작해도 자동 셔플 후 배정된다.
- 참가자 전원이 정확히 한 조에만 배정된다.
- 가중치를 포함한 조별 점수 규칙을 지킨다.
- 배정 연출 중 중복 실행이나 명단 변경이 불가능하다.
- 연출을 건너뛰거나 브라우저를 닫아도 최종 결과가 동일하다.
- 늦게 추가한 참가자는 기존 조를 바꾸지 않고 추가 배정된다.
- 동작 줄이기 환경에서 지연 없이 전체 결과가 표시된다.

## 이번 기획에서 제외

- 입력 순서를 기준으로 한 배정
- 참가자별 조 선택 또는 고정
- 특정 참가자끼리 묶기·떼기
- 전체 재추첨 버튼
- 서버 저장과 여러 기기 동기화
