# 랜덤 조 편성 — PWA 품질 검증 계획

## 목적

P3 품질 검증과 P4 공개 전환 여부를 판단하기 위한 수동 검증 계획이다. 이 문서는 테스트 절차와
합격 기준만 정의하며 제품 코드 변경을 승인하지 않는다. 실패 항목은 재현 조건과 증거를 기록한 뒤
별도 수정 범위로 다시 승인한다.

## 대상 기준선

- 배포 대상: GitHub Pages의 `main` 최신 성공 배포
- Manifest 표시 방식: `standalone`
- 로컬 저장 키: `random-team-draw.session.v1`
- Service Worker 캐시: `random-team-draw-v2`
- 주요 데이터: 참가자, 최근 배정 ID, 조 이름 네 개, 조별 가중치 네 개

검증을 시작할 때 커밋 SHA, 공개 URL, 브라우저 버전과 실행 날짜를 결과표에 기록한다.

## 환경 매트릭스

### 필수 환경

| 구분 | 환경 | 확인 범위 |
|---|---|---|
| D1 | Windows 11 + Edge 최신 안정판 | 웹 실행, 설치, 독립 창, 오프라인, 업데이트 |
| D2 | Windows 11 + Chrome 최신 안정판 | 웹 실행, 설치 가능 여부, 입력과 저장 |
| M1 | Android + Chrome 최신 안정판 | 홈 화면 추가, 세로 화면, 터치, 오프라인 |

### 선택 환경

| 구분 | 환경 | 확인 범위 |
|---|---|---|
| D3 | Windows 10 + Edge | 지원 환경 회귀 확인 |
| M2 | iPhone + Safari | 홈 화면 추가와 기본 기능 확인 |

필수 환경 중 하나라도 확보하지 못하면 P3를 완료로 표시하지 않고 `미검증`으로 남긴다.

## 공통 준비

1. 새 브라우저 프로필 또는 사이트 데이터가 없는 상태에서 시작한다.
2. 개발자 도구 Application 영역에서 Manifest, Service Worker, Cache Storage를 확인할 수 있게 한다.
3. 테스트용 조 이름은 `새싹`, `열매`, `믿음`, `소망`을 사용한다.
4. 기본 가중치 검증 후 `[-1, 0, 1, 0]` 조합도 확인한다.
5. 참가자 예시는 서로 겹치지 않는 한글 이름 12개를 준비한다.
6. 실제 개인정보는 입력하지 않는다.

## 핵심 기능 검증

### F-01 참가자 추가와 균형 배정

1. 참가자 네 명을 차례로 추가한다.
2. 각 조에 한 명씩 배정되는지 확인한다.
3. 다섯 번째 참가자를 추가한다.

**합격:** 첫 네 명은 네 조에 한 명씩 배정되고, 이후에도 조별 점수 최솟값 후보에만 배정된다.

### F-02 빠른 입력과 중복 방지

1. 한글 이름을 조합 중인 상태에서 Enter를 사용한다.
2. 같은 이름을 앞뒤 공백과 대소문자 차이를 포함해 다시 입력한다.
3. Enter를 빠르게 여러 번 누른다.

**합격:** 조합 중 오등록과 중복 참가자가 생기지 않고 오류 안내가 입력 영역에 표시된다.

### F-03 수정과 삭제

1. 참가자 이름을 수정한다.
2. 수정 전후 조가 같은지 확인한다.
3. 최근 배정자가 아닌 참가자를 삭제한다.
4. 최근 배정자를 삭제한다.

**합격:** 수정·삭제가 다른 참가자의 조를 바꾸지 않고, 최근 배정자 삭제 시 결과 카드가 사라진다.

### F-04 설정과 가중치

1. 조 이름 네 개를 변경하고 저장한다.
2. 참가자 명단, 결과 카드, 네 조 카드에 즉시 반영되는지 확인한다.
3. 가중치를 `[-1, 0, 1, 0]`으로 설정하고 여러 명을 추가한다.
4. 빈 이름과 20자 초과 이름을 저장해 본다.

**합격:** 설정은 모든 표시 영역에 일관되게 반영되고, 가중치 점수가 낮은 조가 우선되며 잘못된
조 이름은 저장되지 않는다.

### F-05 전체 초기화

1. 참가자와 사용자 설정이 있는 상태에서 전체 초기화를 누른다.
2. 취소 후 데이터가 유지되는지 확인한다.
3. 다시 실행해 승인한다.

**합격:** 참가자와 최근 배정만 사라지고 조 이름과 가중치는 유지된다.

## 설치와 오프라인 검증

### P-01 Manifest와 설치

1. 공개 URL을 연다.
2. Manifest 이름, 아이콘, 시작 URL, 범위를 확인한다.
3. 브라우저 설치 UI 또는 앱의 설치 버튼으로 설치한다.
4. 설치 앱을 시작 메뉴에서 실행한다.

**합격:** 독립 창으로 열리고 공개 URL과 동일한 데이터와 기능을 제공한다.

### P-02 오프라인 시작

1. 온라인 상태에서 앱을 한 번 완전히 연다.
2. 참가자와 설정을 저장하고 창을 닫는다.
3. 네트워크를 끈 뒤 설치 앱을 다시 연다.
4. 새 참가자를 추가하고 창을 닫았다가 다시 연다.

**합격:** 화면이 정상 표시되고 온라인에서 만든 데이터와 오프라인 변경이 모두 유지된다.

### P-03 업데이트

1. 현재 버전에서 참가자와 설정을 저장한다.
2. Service Worker 캐시 버전이 변경된 시험 배포를 적용한다.
3. 실행 중인 창과 새로 연 창에서 업데이트 반영 시점을 확인한다.
4. 새로고침과 재실행 후 데이터를 확인한다.

**합격:** 새 앱 셸로 전환되고 이전 앱 캐시는 제거되며 `localStorage` 데이터는 유지된다.

## 반응형·접근성 검증

### U-01 모바일 화면

- 320px 수준의 좁은 세로 화면에서 가로 스크롤이 생기지 않는다.
- 참가자 행과 설정 버튼이 겹치거나 잘리지 않는다.
- 모든 버튼을 터치로 안정적으로 누를 수 있다.
- 키보드가 열린 상태에서도 입력 오류와 추가 버튼을 확인할 수 있다.

### U-02 키보드와 포커스

- Tab 순서가 입력 → 추가 → 참가자 조작 → 설정 → 초기화 흐름을 따른다.
- 설정 대화상자를 닫으면 합리적인 위치로 포커스가 돌아온다.
- Enter 등록 후 이름 입력에 포커스가 유지된다.
- 포커스 위치가 테두리 등으로 명확히 보인다.

### U-03 보조 기술과 동작 줄이기

- 오류와 저장 상태 변경을 화면 읽기 도구가 인지할 수 있다.
- 버튼의 목적이 텍스트 또는 접근 가능한 이름으로 전달된다.
- OS의 동작 줄이기 설정에서 배정 이동 애니메이션이 실행되지 않는다.
- 색상을 제외해도 조 이름과 상태를 구분할 수 있다.

## 장시간·경계 검증

- 참가자 100명을 추가해 입력과 스크롤 반응을 확인한다.
- 이름 1자, 30자, 31자를 각각 확인한다.
- 조 이름 1자, 20자, 21자를 각각 확인한다.
- 가중치 -10과 +10 경계에서 버튼이 범위를 넘지 않는지 확인한다.
- 저장 데이터 일부가 없거나 잘못된 형태일 때 기본값으로 안전하게 보정되는지 확인한다.
- 시크릿 모드와 일반 모드 데이터가 공유되지 않음을 확인한다.

## P3 종료 기준

- D1, D2, M1의 필수 시나리오가 모두 통과한다.
- 데이터 손실, 앱 시작 실패, 잘못된 조 배정 문제는 0건이다.
- 키보드·터치로 핵심 기능을 완료할 수 없는 문제는 0건이다.
- 그 밖의 알려진 문제는 재현 조건, 영향도, 우회 방법을 문서화한다.
- 검증 결과에 실행 날짜, 환경, 커밋 SHA와 판정 근거가 남아 있다.

종료 기준을 만족한 뒤에만 P4 공개 전환 완료와 후속 기능 상세 기획으로 이동한다.
