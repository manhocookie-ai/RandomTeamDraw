# 랜덤 조 편성 — 제품 기획

## 제품 방향

랜덤 조 편성은 서버 없이 동작하는 **설치형 정적 웹앱(PWA)** 으로 제공한다. 사용자는
웹 주소로 바로 실행하거나 Windows와 모바일의 홈 화면에 설치할 수 있다. 웹과 Windows용
기능을 따로 구현하지 않고 `web/` 코드 하나를 모든 환경에서 사용한다.

기존 WPF 앱은 PWA 전환이 완료될 때까지만 동작 비교와 데이터 형식 참고용으로 유지한다.
새 기능은 PWA에만 구현하며, 전환 완료 후 WPF 실행 파일 배포는 종료한다.

## 목표

- 웹, 설치된 Windows 앱, 모바일에서 같은 화면과 기능을 제공한다.
- 첫 방문 이후에는 네트워크가 없어도 실행할 수 있다.
- 참가자와 설정은 사용 중인 브라우저·설치 앱의 로컬 저장소에만 보관한다.
- 기능 수정과 배포는 하나의 코드베이스에서 한 번만 수행한다.

## 포함 범위

1. 참가자 추가·수정·삭제와 전체 초기화
2. 최소 인원 조 우선 배정과 동률 시 암호학적 무작위 선택
3. 최근 배정 참가자 표시와 강조
4. 조 이름 및 조별 가중치 설정
5. 브라우저 `localStorage` 자동 저장과 재실행 복원
6. PWA 설치, 독립 창 실행, 앱 아이콘, 오프라인 앱 셸
7. GitHub Pages 자동 배포

## 제외 범위

- 사용자 계정, 서버, 데이터베이스, 기기 간 자동 동기화
- 별도 Windows 네이티브 UI와 WebView2 포장 앱
- 개별 재추첨, 삭제 Undo, 별도 추첨 화면
- 앱 업데이트를 위한 별도 설치 프로그램

## 배정 및 입력 규칙

1. `현재 인원 + 설정 가중치`가 가장 작은 조를 선택한다.
2. 최솟값이 같은 조가 여러 개면 `crypto.getRandomValues()`로 하나를 선택한다.
3. 이름 수정은 참가자 ID와 소속 조를 바꾸지 않는다.
4. 참가자 삭제는 다른 참가자의 조를 다시 계산하지 않는다.
5. 참가자 이름은 공백이 아닌 30자 이하이며 중복을 막는다.
6. 조 이름은 공백이 아닌 20자 이하 문자열이어야 한다.
7. 가중치는 -10부터 +10까지 허용한다.

## 로컬 데이터

- 저장 키: `random-team-draw.session.v1`
- 데이터: 참가자, 최근 배정 ID, 조 이름 네 개, 조별 가중치 네 개
- 모든 정상 변경 직후 같은 브라우저의 `localStorage`에 저장한다.
- 전체 초기화는 참가자와 최근 배정만 지우고 조 이름과 가중치는 유지한다.
- 앱 업데이트와 캐시 갱신이 기존 로컬 데이터를 삭제해서는 안 된다.
- 브라우저 데이터 삭제, 시크릿 모드, 다른 브라우저·기기에서는 데이터가 공유되지 않는다.

## PWA 요구사항

- Manifest에 앱 이름, 시작 경로, `standalone` 표시 방식, 테마색과 아이콘을 정의한다.
- Service Worker는 HTML/CSS/JavaScript/아이콘으로 구성된 앱 셸을 캐시한다.
- 첫 온라인 방문 이후 새로고침과 재실행이 오프라인에서도 가능해야 한다.
- 배포된 새 버전은 다음 실행 또는 새로고침에서 안전하게 반영되어야 한다.
- GitHub Pages의 하위 경로에서도 설치와 오프라인 탐색이 정상이어야 한다.

## 전환 원칙

- PWA 기능 동등성과 설치·오프라인 검증 전에는 WPF 소스를 삭제하지 않는다.
- 기능 동등성이 확인되면 README의 기본 실행 방법을 PWA로 바꾼다.
- 이후 요구사항은 PWA에만 반영하며 두 UI를 동시에 유지보수하지 않는다.
- WPF 세션 자동 이전은 하지 않는다. 필요 시 JSON 가져오기·내보내기를 별도 기획한다.

## 완료 기준

- 웹 URL에서 모든 핵심 기능이 동작한다.
- Edge 또는 Chrome에서 앱으로 설치하고 독립 창에서 실행할 수 있다.
- 한 번 접속한 뒤 네트워크를 끊어도 앱이 열리고 로컬 데이터가 유지된다.
- 데스크톱과 모바일에서 주요 조작이 잘리거나 겹치지 않는다.
- `main` 배포 후 GitHub Pages에 새 버전이 자동 반영된다.
- README와 사용자 안내가 PWA 단일 제품 기준으로 정리된다.
