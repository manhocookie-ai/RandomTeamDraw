# 랜덤 조 편성 — PWA 전환 마일스톤

## P0. 방향 확정 — 완료

- PWA를 유일한 제품 코드로 결정
- WPF는 전환 기간의 참고용 레거시로 한정
- 서버와 계정 없이 브라우저 로컬 저장 유지
- 별도 Windows 패키지와 WebView2 래퍼는 제외

## P1. 웹 기능 동등성 — 완료

- 참가자 추가·수정·삭제와 전체 초기화
- 최소 인원 및 가중치 기반 무작위 배정
- 최근 배정 표시와 강조
- 조 이름과 가중치 통합 설정
- 반응형 UI와 `localStorage` 저장

## P2. 설치 및 오프라인 지원 — 구현 완료, 배포 검증 대기

**완료 조건**

- Manifest 및 여러 크기의 앱 아이콘 추가
- Service Worker 앱 셸 캐시와 오프라인 시작 구현
- GitHub Pages 하위 경로에서 자원과 시작 URL 정상 해석
- 설치 가능한 앱으로 브라우저 판정 통과
- 캐시 버전 갱신 시 로컬 사용자 데이터 유지

## P3. 품질 검증

**완료 조건**

- Edge/Chrome 데스크톱 설치 및 독립 창 실행 확인
- Android 설치 또는 홈 화면 추가 확인
- 온라인 최초 실행 후 오프라인 재실행 확인
- 새 배포 후 업데이트 반영 확인
- 한글 입력, 중복, 긴 이름, 빠른 Enter, 다수 참가자 점검
- 작은 화면, 키보드 탐색, 화면 읽기용 레이블 점검

## P4. 공개 배포 및 전환 완료

**완료 조건**

- 개인정보가 제거된 저장소를 공개로 전환
- GitHub Pages 활성화 및 실제 공개 주소 확인
- README 기본 사용법을 웹 접속·PWA 설치 기준으로 변경
- WPF는 레거시 참고용으로 명시하고 신규 기능 개발 중단
- 공개 버전에서 설치·오프라인·로컬 저장 최종 확인

## 진행 규칙

- 가능한 실제 브라우저 동작을 확인하고 완료 처리한다.
- PWA 전환 중 새 기능 요청은 `web/`에만 반영한다.
- WPF와 PWA의 동시 기능 추가를 완료 조건으로 삼지 않는다.
- 설치나 배포가 막히면 코드와 외부 계정 설정 문제를 구분해 기록한다.
