# 랜덤 조 편성 — 향후 제품 기획

## 현재 판단

핵심 기능과 PWA 구현은 이미 갖춰져 있다. 지금은 기능을 추가하기보다 실제 설치·오프라인·모바일
환경을 검증하고 PWA 전환을 끝내는 것이 우선이다. 새로운 기능은 P3·P4 완료 후 실제 사용 의견을
근거로 선택하며, 이 문서는 구현 승인이 아니라 후보 범위와 판단 기준을 기록한다.

## 1순위 — PWA 전환 완료

새 기능보다 먼저 다음 항목을 완료한다.

1. Edge와 Chrome에서 설치 및 독립 창 실행을 확인한다.
2. 최초 온라인 실행 후 네트워크를 끊고 재실행·새로고침을 확인한다.
3. 배포 업데이트 후 기존 참가자, 조 이름, 가중치가 유지되는지 확인한다.
4. Android 세로 화면에서 입력·수정·설정·초기화를 점검한다.
5. 한글 IME, 빠른 Enter, 중복 이름, 긴 명단과 작은 화면을 점검한다.
6. 공개 URL과 README를 PWA 단일 제품 기준으로 정리한다.

이 항목이 끝나기 전에는 WPF 제거, 데이터 형식 변경, 신규 기능 개발을 시작하지 않는다.

## 전환 후 후보 기능

### A. 세션 내보내기·가져오기 — 우선 검토

브라우저 데이터 삭제나 PC 교체에 대비해 현재 상태를 JSON 파일로 보관하고 복원한다.

- 참가자, 최근 배정 ID, 조 이름, 가중치를 한 파일에 포함
- 가져오기 전에 파일 형식과 중복·범위를 검증
- 기존 데이터를 덮어쓰기 전에 명확한 확인 제공
- 서버 업로드 없이 브라우저 안에서만 처리

**도입 조건:** 다른 PC로 옮기거나 행사별 상태를 보관하고 싶다는 요구가 실제로 발생할 때.

### B. 참가자 일괄 입력 — 조건부 검토

여러 줄 이름을 붙여넣어 입력 대기 명단을 만들고, 배정 자체는 현재처럼 한 명씩 공개한다.

- 한 줄에 한 명
- 공백 줄 제거와 중복 사전 표시
- 등록 전 미리보기 및 취소
- 붙여넣는 즉시 전원을 배정하지 않음

**도입 조건:** 한 행사에서 반복 입력하는 참가자가 많아 수기 입력이 병목일 때.

### C. 발표 모드 — 조건부 검토

프로젝터나 TV에서 최근 배정 결과를 더 크게 보여주는 전체 화면 모드다.

- 참가자 이름과 조 이름 중심의 단순 화면
- 클릭, Enter 또는 Esc로 메인 화면 복귀
- 동작 줄이기 설정을 그대로 존중
- 별도 추첨 로직이나 화면 상태를 만들지 않음

**도입 조건:** 실제 사용 장소에서 현재 결과 카드가 멀리서 잘 보이지 않을 때.

### D. 조 색상 설정 — 낮은 우선순위

조 이름과 함께 색상을 고를 수 있게 한다. 색상은 장식이며 조 구분은 항상 이름과 번호로도 제공한다.

**도입 조건:** 여러 행사에서 고정된 팀 색상을 반복 사용한다는 요구가 있을 때.

## 당분간 제외할 기능

- 사용자 계정, 서버 데이터베이스, 로그인
- 여러 기기 실시간 동기화
- 개별 재추첨과 삭제 Undo
- 복잡한 배정 이력·통계 대시보드
- 채팅, 알림, 관리자 권한 체계
- WPF와 PWA 양쪽에 같은 신규 기능을 중복 구현

이 기능들은 앱의 핵심인 `이름 입력 → 즉시 배정` 흐름을 복잡하게 하거나 서버 운영을 요구하므로,
명확한 반복 수요가 확인되기 전에는 범위에 넣지 않는다.

## 기능 채택 기준

후보 기능은 아래 질문에 모두 답할 수 있을 때만 구현 단계로 이동한다.

1. 실제 사용 중 반복해서 발생한 문제가 무엇인가?
2. 기존 화면과 핵심 흐름을 더 복잡하게 만들지 않는가?
3. 서버 없이 브라우저 로컬 환경에서 안전하게 구현 가능한가?
4. 모바일과 설치형 PWA에서 동일하게 사용할 수 있는가?
5. 완료 여부를 검증할 구체적인 시나리오가 있는가?

## 권장 순서

```text
P3 품질 검증
  → P4 공개 배포 및 PWA 전환 완료
    → 실제 행사 사용 의견 수집
      → 세션 내보내기·가져오기 검토
        → 일괄 입력 또는 발표 모드 중 실제 수요가 큰 기능 선택
```

한 번에 하나의 후보만 상세 기획하고, 승인된 기능만 구현한다.
