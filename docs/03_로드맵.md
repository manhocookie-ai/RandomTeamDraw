# 랜덤 조 편성 — PWA 구현 로드맵

## 목표 구조

```text
RandomTeamDraw/
├── web/                       # 유일한 제품 UI 및 로직
│   ├── index.html
│   ├── styles.css
│   ├── app.js
│   ├── manifest.webmanifest
│   ├── service-worker.js
│   └── icons/
├── .github/workflows/
│   └── deploy-pages.yml
├── docs/
└── (WPF 소스)                 # 전환 완료까지 참고용
```

## 구현 순서

1. 앱 이름, 짧은 이름, 시작 URL, 표시 모드와 색상을 Manifest에 정의한다.
2. 마스크 가능 아이콘을 포함한 필수 PWA 아이콘 세트를 만든다.
3. `index.html`에 Manifest, 아이콘, Service Worker 등록 코드를 연결한다.
4. Service Worker에서 버전이 붙은 앱 셸 캐시를 생성한다.
5. 탐색 요청은 네트워크 우선 후 캐시된 시작 화면으로 처리한다.
6. 정적 자원은 캐시 우선으로 제공하고 새 캐시 활성화 시 이전 앱 캐시를 제거한다.
7. GitHub Pages 프로젝트 하위 경로에서 상대 경로를 확인한다.
8. 설치·독립 실행·오프라인 실행·업데이트를 실제 브라우저에서 점검한다.
9. README를 PWA 중심으로 바꾸고 WPF를 레거시 항목으로 이동한다.
10. 저장소 공개 및 Pages 배포 후 공개 URL에서 최종 확인한다.

## 캐시 전략

- 앱 셸은 Service Worker 설치 시 미리 캐시한다.
- HTML 탐색은 네트워크 우선, 실패하면 캐시된 시작 화면을 사용한다.
- CSS, JavaScript, 아이콘은 캐시 우선으로 제공한다.
- Service Worker는 `localStorage`에 접근하거나 사용자 데이터를 지우지 않는다.
- 캐시 이름에 버전을 두고 활성화 시 과거 앱 캐시만 삭제한다.

## 검증 목록

- Manifest가 필수 필드와 아이콘을 포함하는가?
- Service Worker 범위가 앱 전체 경로를 포함하는가?
- 첫 방문 후 오프라인에서 새로고침해도 화면이 열리는가?
- 오프라인에서 변경한 참가자와 설정이 재실행 후 유지되는가?
- 업데이트 후에도 사용자 데이터가 유지되는가?
- 설치된 창과 브라우저 탭의 기능이 동일한가?
- 모바일 세로 화면에서 모든 기능을 사용할 수 있는가?
