# 랜덤 조 편성 — 개발 로드맵

## 구현 순서
1. .NET 10 WPF 프로젝트 생성. 소규모 단일 프로젝트로 시작.
2. `Participant`, `SessionData` 모델과 `TeamAssignmentService` 구현.
3. 배정 로직 테스트: 첫 4명, 동률, 5명 이상, 삭제 후 추가, 이름 수정.
4. `MainViewModel`에 명단·조별 표시·추가/수정/삭제 명령 연결.
5. `MainWindow.xaml`에서 30:70 레이아웃과 2×2 조 카드 구현.
6. 최근 등록자 ID 기반 강조 및 짧은 등장 애니메이션 적용.
   최근 등록자 결과 배너와 `config.json` 기반 조 이름도 함께 적용.
7. `SessionStorageService` 구현: JSON, 안전한 파일 교체, 백업, 복원.
8. 초기화 확인 추가.
9. IME 입력, 빠른 Enter, 중복, 파일 오류, 창 크기, 스크롤 테스트.
10. Release 빌드, win-x64 self-contained 게시, README 작성.

## 권장 구조
```text
RandomTeamDraw/
├── Models/
│   ├── Participant.cs
│   └── SessionData.cs
├── Services/
│   ├── TeamAssignmentService.cs
│   └── SessionStorageService.cs
├── ViewModels/
│   └── MainViewModel.cs
├── MainWindow.xaml
├── MainWindow.xaml.cs
├── App.xaml
└── RandomTeamDraw.csproj
```
구조는 필요할 때만 확장한다. UI 이벤트 처리는 View, 업무 규칙은 Service, 상태 및 명령은 ViewModel에 둔다.

## 테스트 핵심
- 최소 인원 조에만 신규 참가자가 배정되는가?
- 수정·삭제가 다른 참가자의 배정에 영향을 주지 않는가?
- 중복 이름/빈 이름/한글 IME 입력을 안전하게 처리하는가?
- 모든 변경 후 재실행하면 정확히 복원되는가?
- 저장 중 종료·파일 손상 시 데이터 손실을 최소화하는가?
- 전체 초기화 후 이전 데이터가 되살아나지 않는가?

## Codex 작업 방식
- 마일스톤 단위로 구현하고 가능하면 각 단계에서 빌드·테스트한다.
- 오류가 발생하면 원인과 수정 내용을 보고한다.
- Windows 외 환경에서는 WPF 실행 검증의 한계를 명확히 밝힌다.
- 요구사항 밖 기능은 임의 추가하지 않는다.
